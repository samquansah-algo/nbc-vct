## Earlier: v1 → v2

*Why v1 and v2 were first kept as separate versions, and what changed between them.*

| Version | Title | Status | Core bet |
|---|---|---|---|
| **v1** | [The Human Capability Utility](v1-human-capability-utility/THESIS.md) | Main frame of v3 | **Infrastructure economics:** community-owned intelligence infrastructure that becomes productive, so schools and communities *participate* in the intelligence economy rather than only consuming it |
| **v2** | [NBC: Infrastructure for the Next Billion Children](v2-nbc-infrastructure/THESIS.md) | Merged into v3 | **Institutional portability:** make the intelligence of a great school portable, so high-capability learning environments become cheap to instantiate anywhere |

## Why versions, not a merge

1. **They make different primary claims.** v1 stands or falls on whether shared intelligence infrastructure can produce enough economic value to be financed as a productive community asset. v2 stands or falls on whether institutional intelligence (curriculum, teacher development, administration, evidence) can be separated from buildings and replicated. A merged document would hide which claim a given experiment is testing.
2. **The shared core is already identical.** Both rest on computational matter, computational tokens, an Experience Protocol, a Capability Graph, Village AI, evidence without surveillance, Proof of Human Capability, and nearly the same first prototype (v1 §XIX, v2 §30). There is nothing to gain by merging that part; it is common ground.
3. **Decision history matters.** Under the VCT discipline, knowing what was believed, and why it changed, is part of the evidence record.

## v1 claims parked, not rejected

These v1 ideas are not in v2. They should re-enter only through evidence, in roughly this order:

| Parked claim | Condition for revisiting |
|---|---|
| Nodes as **productive community assets** with use outside school hours (v1 §IX) | A first node shows reliable uptime and measurable non-school demand (adult learning, community services) without displacing children's use |
| **Blended infrastructure finance** measured by total infrastructure productivity (v1 §XIII) | Cost per verified capability gain is measured for at least one node; a financier is willing to model it |
| **Intelligence Credits and Contribution Credits** (v1 §XII) | The Contribution Protocol shows teachers create and share worlds with attribution alone; only then test whether credits add anything |
| **Frontier-AI evaluation market** (v1 §X, §XVIII) | One AI lab pays for a set of human-designed physical-reasoning worlds built for evaluation only (no child data) |
| **The intelligence grid** as a network topology (v1 §XIV) | Multiple nodes are running and synchronizing; the regional layer has a real job to do |

## What would justify a v3

A v3 should be written **after** the first node's results, not before. It would either:
- **Confirm v2's institutional core** and bring back the v1 economic layer where the evidence above supports it; or
- **Narrow the thesis** to whichever claim survived (for example, "evidence of transfer across worlds" alone) if the institutional claims fail.

Rule of thumb: **new version when a core claim changes; edit in place only for wording.**
